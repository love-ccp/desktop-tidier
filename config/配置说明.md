# 配置编写说明（config.json）

> 配置文件是**严格 JSON**（不支持注释）。首次运行时程序会在配置目录自动生成全套文件。
> 编辑建议：用支持 JSON Schema 的编辑器（VS Code 等）打开，`"$schema"` 字段会触发字段补全与实时校验。

## 配置目录里有哪些文件？改哪个？

配置目录（Windows `%APPDATA%\desktop-tidier\`，Linux `~/.config/desktop-tidier/`）**扁平布局、无歧义**：

| 文件 | 作用 | 是否生效 |
|---|---|---|
| **`config.json`** | **唯一生效的配置**。想改任何行为就改它 | ✅ **生效** |
| **`lexicon.txt`** | **唯一生效的词库**（关键词→分组） | ✅ **生效** |
| `schema.json` | JSON Schema，仅供编辑器补全/校验提示 | ❌ 仅参考 |
| `config.example.json` | 参考示例（与 `config.json` 初始内容一致） | ❌ 仅参考 |
| `配置说明.md` | 本文档 | ❌ 仅参考 |
| `storage/` | 待分类 / 课件库 / 归档 / 台账 / `state.json`（程序自动维护） | 运行数据 |
| `logs/` | 日志（`desktop-tidier.log`，必要时 `startup-error.log`） | 运行数据 |

一句话：**生效的就两个 —— `config.json` 和 `lexicon.txt`，其余全是参考和程序自己维护的数据。** `config.example.json` 只是"出厂模板"的备份，改它不会影响程序。

## 处理流程

```
桌面 source_dir ──(后缀 + mtime 超过 min_age_days 天)──> inbox_dir（指定目录）
inbox_dir ──(词库关键词匹配)──> course_dir/{分组}/（无匹配 → {default_group}/）
course_dir/** ──(每 interval_hours 压缩归档，默认一周)──> archive_dir/{rename_pattern}.zip
```

- 每次"收录"（文件从桌面进入课件库）都会按 `indexer.entry_format` 追加一条台账记录，编号顺延。
- **整理与归档完全解耦**：整理完**不会**立即归档；归档只按 `archiver.interval_hours` 自己的周期执行（默认 168 小时 = 一周），包括托盘「立刻整理」也只整理、不归档。
- **归档前比对台账**：本次台账新增文件数（= 当前最大编号 − 上次归档时的编号）低于 `archiver.min_new_files` 时，跳过本次归档，课件库文件继续保留，等下次周期累计够数再归档。
- **归档总量管理**：归档目录里的 zip 超过 `max_archives`（数量）或 `max_total_bytes`（总字节）上限时，从最旧的开始把多余的 zip 移入回收站（0 = 不限制）。

### 宽松间隔与启动追赶

班级电脑不是全天开机，"恰好每 N 天整理一次"会被关机饿死。因此间隔按**「至多每隔 N」宽松执行**：

- 程序运行时照常按周期执行；
- **每次启动 15 秒后检查**：距上次整理 ≥ `scan_interval_secs` → 立即补一次整理；距上次归档 ≥ `interval_hours` → 立即补一次归档（先整理后归档）。
- 上次整理/归档时间记录在 `storage/state.json`（程序自动维护，勿手改；损坏会自动重建，不影响运行）。

## 字段逐一说明

### watcher（监听与筛选）

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `source_dir` | string | `""` | 源目录（要整理的桌面）。**留空 = 自动探测系统桌面**。Windows 如 `C:/Users/教师/Desktop`，Linux 如 `/home/教师/Desktop`。 |
| `extensions` | string[] | 见示例 | 要移动的**后缀列表**，不带点、小写。希沃课件常见 `enbx`（希沃课件格式）、`pptx/ppt`、`doc/docx`、`pdf`、`wps/et/dps`。 |
| `min_age_days` | int | `3` | 文件**修改时间**超过 N 天才处理（已锁定用 mtime，非创建时间）。 |
| `debounce_ms` | int | `400` | 文件事件防抖（毫秒），避免瞬间大量事件重复处理。 |
| `scan_interval_secs` | int | `172800` | **扫描整理频率**（秒）。默认 `172800` = 两天；按「至多每隔 N」宽松执行（见上文启动追赶）。 |

### storage（目录）

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `inbox_dir` | string | `storage/待分类` | 步骤 1 的"指定目录"。 |
| `course_dir` | string | `storage/课件库` | 步骤 2 的分组根；文件最终进 `course_dir/{分组}/`。 |
| `archive_dir` | string | `storage/归档` | 步骤 3 的 zip 归档目标。 |
| `recycle_after_archive` | bool | `true` | 归档成功后是否把 `course_dir` 内文件**清空到回收站**（可恢复，非彻底删除）。 |

> 所有相对路径均相对于**配置文件所在目录**。建议保持相对路径，便于整套目录随 exe 拷走。

### classifier（关键词分类）

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `lexicon_path` | string | `lexicon.txt` | 词库路径（默认与 config.json 同目录，即配置目录里的 `lexicon.txt`）。 |
| `lexicon_encoding` | string | `auto` | 词库编码：`auto`（chardetng 自动探测）/ `utf-8` / `gbk`。 |
| `default_group` | string | `未分类` | 文件名未命中任何关键词时的分组。 |

### archiver（压缩归档）

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `interval_hours` | int | `168` | **归档周期（小时）**，默认 `168` = 一周。整理完成不会立即归档，只按本周期（含启动追赶）执行。 |
| `zip_level` | int | `6` | zip 压缩等级，**需求固定为 6**（1~9，越高越慢越小）。 |
| `rename_pattern` | string | `{date}_{seq}_desktop-tidier.zip` | 归档文件重命名规则。占位符：`{date}`=日期 `%Y%m%d`、`{time}`=时间 `%H%M%S`、`{seq}`=当日序号（自动递增，避免重名）。 |
| `max_archives` | int | `0` | 归档 zip **最大保留数量**；`0` = 不限制。超出时从最旧开始把多余的 zip 移入回收站。 |
| `max_total_bytes` | int | `0` | 归档 zip **最大总占用字节**；`0` = 不限制。超出时从最旧开始把多余的 zip 移入回收站。 |
| `min_new_files` | int | `1` | **归档前比对台账**：本次新增文件数低于该值则跳过本次归档；`0` = 不限制（总是归档）。默认 `1` 即"没有新文件就不打空包"。 |

> 上限管理只统计 `archive_dir` 顶层的 `*.zip`，且绝不删除本次刚生成的归档。

### indexer（MD 台账）

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `md_path` | string | `storage/台账.md` | 台账文件路径。 |
| `md_encoding` | string | `auto` | 读取现有文件编码后**按相同编码顺延追加**；`auto`=自动探测。 |
| `entry_format` | string | `{no}. {filename} - {group} - {date}` | 单条记录格式。占位符：`{no}`=编号（顺延）、`{filename}`=文件名、`{group}`=分组、`{date}`=操作日期（授时校正后的本地日期 `%Y-%m-%d`）。 |

### logger（日志，单文件）

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `file` | string | `logs/desktop-tidier.log` | 日志文件。始终只有一个日志文件。 |
| `level` | string | `info` | `trace`/`debug`/`info`/`warn`/`error`。 |
| `max_bytes` | int | `1048576` | 超过此字节数后，旧日志改名 `.bak`（仅保留 1 份），新建同名文件继续写。 |

### timesync（授时）

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `enabled` | bool | `true` | 是否启用授时。 |
| `servers` | string[] | `["https://www.baidu.com"]` | HTTPS 授时 URL 列表，**读取响应 `Date` 头**；依次尝试直到成功。国内建议用可直连站点。 |
| `interval_hours` | int | `1` | 启动时立即授时一次，之后每隔 N 小时授时并落盘偏移。 |
| `timeout_secs` | int | `10` | 单次请求超时（秒）。 |

> 授时失败不阻塞程序：退回本地时钟，保留上次偏移，并在日志记录。

### notify（系统通知）

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `enabled` | bool | `true` | 系统通知总开关（想完全静默就设 `false`）。 |
| `app_name` | string | `课件整理助手` | 通知来源名。 |

### concurrency（并发）

| 字段 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `max_parallel_ops` | int | `4` | 并发文件操作数（移动/归档）。学校机械盘建议 2~4，SSD 可 8。 |

## 校验错误格式（示例）

坏配置会**跳过整个配置文件、保留旧值**，并发送系统通知。错误消息形如：

```
配置校验失败：字段 "watcher.min_age_days" 期望 非负整数(0~36500)，实际得到 "abc"
建议：请改为整数，例如 3
```

错误级别日志同样会触发系统通知（受 `notify.enabled` 控制）。

## 热重载

- 修改 `config.json` 或 `lexicon.txt` 后，程序检测到文件变更会自动重载（防抖 400ms）；配合托盘"打开配置文件目录"即可边改边生效。
- 新配置先解析到临时结构，**校验通过才原子替换**；失败则保留旧配置并发通知。
- 词库每行独立解析，**单行出错仅跳过该行**并通知，不中断整体加载。

## 词库（lexicon.txt）

每行一条 `关键词<TAB>分组`；`#` 开头为注释；空行跳过。关键词按**整条文件名（含扩展名）**、ASCII 大小写不敏感匹配。示例：

```
# 关键词<TAB>分组
二次函数	数学
三角函数	数学
牛顿定律	物理
电磁感应	物理
```

## 托盘菜单（固定 4 项，自上而下）

右键托盘图标（**刷子样式**；左键同样弹出）出现的菜单固定为：

1. **设置开机自启**：勾选态切换，写入系统开机自启（Windows 注册表 Run 键 / Linux `~/.config/autostart/*.desktop`），点击即切换并同步勾选态。
2. **立刻整理**：立即执行一次整理（扫描 → 分类 → 移动 → 记账），不等 `scan_interval_secs`；**不触发归档**（归档只按 `archiver.interval_hours` 周期）。
3. **打开配置文件目录**：用系统文件管理器（explorer / xdg-open）打开配置目录，方便编辑 `config.json` / `lexicon.txt`。
4. **退出**：优雅退出（各任务 graceful shutdown → 释放单实例锁 → 删除托盘图标）。

> 开机自启状态存在操作系统中，不写入配置文件；程序启动时读 `is_autostart_enabled` 显示勾选态。
